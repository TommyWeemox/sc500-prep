## 1.1 Microsoft Entra ID

| Sujet | À retenir |
| --- | --- |
| PIM | Eligible = à activer ; Active = immédiat. Activation **1 à 24 h**. Exigences : MFA ou **contexte d'authentification**, justification, ticket, approbation (≥ 1 approbateur, 2 recommandés). Licence **P2 ou ID Governance** pour éligibles, approbateurs, réviseurs |
| PIM, gestion | Rôles Entra : Privileged Role Administrator ou Global Administrator. Rôles Azure : Owner ou User Access Administrator |
| PIM, licence expirée | Éligibles **supprimées** ; actives limitées deviennent **permanentes** |
| PIM, Azure IAM | Éligible seulement pour des utilisateurs ou groupes (pas SP ni MI), portées MG, abonnement, RG |
| Accès conditionnel | **P1** ; risque = **P2**. Évalué **après le 1er facteur**. Toutes les politiques s'appliquent (ET), **Block** l'emporte. Report-only et What If avant activation |
| Authentication strengths | MFA, Passwordless MFA, **Phishing-resistant MFA**. Incompatible avec « Require MFA » dans la même politique |
| Phishing-resistant | WHfB, Platform Credential macOS, passkeys (FIDO2, synced, Authenticator), CBA. Authenticator phone sign-in = passwordless mais **pas** résistant au phishing |
| TAP | 1er facteur + MFA, pour l'amorçage passwordless |
| Comptes d'urgence | ≥ 2, cloud-only, GA **actif permanent**, FIDO2 ou CBA, **exclus** des politiques qui bloquent, alerte, test tous les **90 jours** |
| Apps | App registration = application object (global, home tenant). Enterprise app = service principal (local). Préférer certificat ou **federated credential** au secret |
| Consentement | Délégué = au nom de l'utilisateur (borné par ses droits). Application = sans utilisateur, **admin seulement**. `microsoft-user-default-low` = éditeurs vérifiés + permissions low impact. Admin consent workflow |
| Identités managées | System = 1 ressource, même cycle de vie. User = partagée, cycle indépendant, préautorisation possible |

## 1.2 Azure Key Vault

| Sujet | À retenir |
| --- | --- |
| SKU | Standard (logiciel) ; Premium (+ HSM) ; Managed HSM = clés seulement |
| Soft-delete | Toujours actif. Rétention **7 à 90 j**, défaut **90**, fixée **à la création**. Nom réservé pendant la rétention |
| Purge protection | Désactivée par défaut ; empêche la purge avant la fin de rétention. Exigée par le chiffrement CMK |
| Accès | **RBAC par défaut** (API 2026-02-01). Secrets User (lire), Secrets Officer (gérer), Crypto Service Encryption User (wrap/unwrap), Reader (métadonnées), Contributor (plan de contrôle). Access policy : un Contributor peut s'auto-attribuer les données |
| Réseau | Pare-feu off par défaut. Règles IP **publiques IPv4** uniquement (pas RFC 1918), 1 000 IP, 200 VNet. Plan de **données** seulement. Accès public désactivé = private endpoint (+ trusted services). NSP « Secure by perimeter » bloque même les trusted services |
| Scan de secrets | VM : **Defender CSPM** ou **Defender for Servers P2** ; déploiements cloud et dépôts : Defender CSPM |
| Defender for Key Vault | Alertes d'accès anormal. Réponse : identifier, contenir, mesurer, **rotation** |

## 1.3 Gouvernance

| Sujet | À retenir |
| --- | --- |
| Policy, effets | disabled → append/modify → **deny** → audit → manual → auditIfNotExists → denyAction ; puis AINE/DINE après succès |
| Policy, remédiation | modify et deployIfNotExists = **identité managée** ; existant = **tâche de remédiation** ; rôles donnés par UAA ou Owner |
| Policy, conflits | Cumulatif, **le plus restrictif l'emporte** ; exclure la portée enfant de l'affectation parente. Évaluation toutes les 24 h |
| Exclusion vs exemption | notScopes sur l'affectation vs objet Exemption (Waiver/Mitigated, expiration) |
| Conformité | MCSB par défaut ; autres standards = **plan payant**. Évaluations ~12 h. Recommandations personnalisées KQL = **Defender CSPM** |
| Verrous | CanNotDelete / ReadOnly, pour **tous**, Owner compris ; **plan de contrôle seulement**. ReadOnly casse List Keys, start/restart VM |
| Rôles | Owner (tout), Contributor (sans accès), UAA (accès seulement). Custom Azure : 5 000/tenant, NotActions ≠ refus, DataActions non attribuable au MG. Custom Entra : P1/P2, PRA, portée annuaire ou app registration |
| Droits excessifs | Revues d'accès, PIM, **CIEM** (Defender CSPM, multicloud) |
| Backup | Soft delete 14 j (enhanced, always-on), **immutable vault** verrouillé, **MUA + Resource Guard**, CMK, private endpoints. Excellent = immuable/always-on **et** MUA |
| IaC | Microsoft Security DevOps `categories: 'IaC'` : Template Analyzer, Checkov, Terrascan ; résultats dans DevOps security |

## Pièges fréquents du domaine

- Confondre « passwordless » et « phishing-resistant ».
- Croire qu'une politique ciblant un rôle contrôle l'**activation** PIM (il faut un contexte d'authentification).
- Croire qu'un verrou protège les **données** d'un compte de stockage.
- Croire qu'une affectation Policy plus permissive à un niveau inférieur lève un **deny** hérité.
- Ajouter une IP **privée** au pare-feu Key Vault.
- Oublier que le **Contributor** d'un coffre en access policy peut lire les secrets.
