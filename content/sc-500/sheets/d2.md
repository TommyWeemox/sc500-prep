## 2.1 Stockage

| Sujet | À retenir |
| --- | --- |
| Autorisation (meilleur → pire) | Entra ID + RBAC (identité managée) → **user delegation SAS** → SAS service/compte (clé) → Shared Key → anonyme |
| Shared Key interdite | Seules Entra et user delegation SAS passent. **Requis** pour l'accès conditionnel sur le stockage |
| SAS | User delegation = Entra ; service et compte = clé. Génération **non auditée**, non comptée. Service SAS sans policy : **≤ 1 h** |
| Stored access policy | Service SAS seulement, **5** par conteneur ; révocation = supprimer, renommer, faire expirer |
| Révocation | Clé : régénérer. User delegation : révoquer la clé de délégation |
| Pare-feu | Règles VNet (**400**), IP publiques (**400**), instances de ressource, services de confiance. Service endpoint ⇒ IP privée ⇒ règle IP inutile |
| Defender for Storage | Activity monitoring, **malware scanning** (au Go, plafond **10 000 Go**/compte/mois par défaut, alertes 75 % et 100 %), sensitive data. **Sans journaux** |
| Protection des données | Soft delete blobs et conteneurs, versioning, immutabilité ; verrou = compte seulement |

## 2.2 Bases de données

| Sujet | À retenir |
| --- | --- |
| Réseau | Pare-feu IP et règles VNet pour SQL DB (**pas MI**). Private endpoint, accès public désactivé. TLS toujours imposé |
| Identité | Un admin Entra par serveur (utiliser un **groupe**). **Entra-only** coupe toute auth SQL. Entra n'est pas RBAC : créer les principaux dans la base |
| TDE | Par défaut sur les nouvelles bases ; au repos. Protecteur géré par le service (rotation annuelle) ou **BYOK** (Key Vault/Managed HSM) ; clé perdue = base inaccessible. BACPAC non chiffré |
| Always Encrypted / masking | AE contre les privilégiés (chiffrement client) ; masking = affichage, pas de chiffrement |
| Audit SQL DB | Stockage, Log Analytics, Event Hubs ; serveur ou base ; échecs de connexion Entra **absents** (voir journaux Entra) |
| Audit MI | Diagnostic **SQLSecurityAuditEvents** + `TO EXTERNAL_MONITOR` ; ou `TO URL` ; support Microsoft : `OPERATOR_AUDIT = ON` |
| Defender | Azure SQL DBs (SQL DB, MI, Synapse) ; SQL on machines (VM, **Arc**) ; Open-source (PostgreSQL, MySQL, RDS ; pas Arc) ; Cosmos DB |

## 2.3 Réseau

| Sujet | À retenir |
| --- | --- |
| NSG | 100-4096 ; défauts 65000/65001/65500 ; stateful ; entrant sous-réseau puis carte |
| ASG | Groupes de cartes par rôle, même VNet |
| AVNM security admin | Avant les NSG, niveau VNet ; **Allow** (NSG décident), **Always Allow** et **Deny** (court-circuit). Une config par région |
| Virtual WAN | Routing intent : **Internet** et **Private** traffic policies, une de chaque par hub ; 0.0.0.0/0 ne passe pas entre hubs ; pas de tables personnalisées |
| VPN | S2S : politiques IPsec/IKE personnalisées. P2S : Entra ID ⇒ accès conditionnel |
| Entra Private Access | Client GSA + connecteur ; Quick Access vs app per-app ; accès conditionnel par app |
| Private endpoint | IP privée vers **une** ressource ; DNS privé ; n'éteint pas l'accès public ; network policies du sous-réseau pour NSG/UDR |
| Private Link service | Publier son service derrière un **Standard LB** |
| Azure Firewall | Premium seul : **TLS sortant, IDPS, URL filtering**. Basic 250 Mb/s, Standard 30 Gb/s, Premium 100 Gb/s |
| Network Watcher | IP flow verify / NSG diagnostics, effective security rules, next hop, connection troubleshoot, **VNet flow logs** (NSG flow logs retirés le 30/09/2027) |

## Pièges fréquents du domaine

- Mettre une IP privée dans un pare-feu PaaS (stockage, Key Vault).
- Croire qu'un private endpoint ferme l'accès public.
- Confondre private endpoint (consommer) et Private Link service (publier).
- Chercher un échec de connexion Entra dans l'audit SQL.
- Activer Defender for Open-Source Relational Databases pour un SQL Server on-premises.
- Utiliser une security admin rule **Allow** pour « garantir » un flux (il faut **Always Allow**).
